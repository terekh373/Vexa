## 1. Призначення документа

Документ фіксує три відхилення реалізації від технічного завдання, затвердженого 21–22.07.2026. Відхилення стосуються вибору технологій і не змінюють ані функціональний обсяг MVP (розділ 3.3 ТЗ), ані критерії приймання (розділ 21 ТЗ).

## 2. Зміна 2.1 — мова розробки веб-клієнта

**Розділ ТЗ:** 6 «Інструменти та програмне забезпечення»

| | |
|---|---|
| **Було** | React + TypeScript для фронтенду |
| **Стало** | React + JavaScript (JSX), збірник Vite |

**Обґрунтування.** Дипломний проєкт має жорсткий термін, а команда фронтенду вже має напрацьований обсяг коду на JavaScript. Переведення наявної кодової бази на TypeScript коштувало б 2–3 робочих дні одного розробника й затримало б критичний шлях (каталог → конструктор → оплата).

**Компенсаційні заходи.**
- Серверна частина, спільний пакет `packages/shared` і мобільний застосунок лишаються на TypeScript зі строгою типізацією.
- Контракт між клієнтом і сервером документується у файлі `docs/frontend-api-map.md`; оновлення цього файлу — обов'язковий пункт чеклиста кожного pull request, що змінює відповідь API.
- Статичний аналіз веб-клієнта виконує oxlint, підключений як окремий обов'язковий чек CI.

## 3. Зміна 2.2 — фреймворк серверної частини

**Розділ ТЗ:** 6 «Інструменти та програмне забезпечення»

| | |
|---|---|
| **Було** | Node.js + NestJS (TypeScript) |
| **Стало** | Node.js + Express 5 (TypeScript) |

**Обґрунтування.** Express дає менший поріг входу для команди й суттєво менше службового коду за того самого результату в межах обсягу MVP. Архітектурна вимога ТЗ щодо шаровості збережена повністю: маршрути → контролери → сервіси → репозиторії, бізнес-логіка лише в сервісах, робота з БД лише в репозиторіях.

**Незмінним лишається:** TypeScript, PostgreSQL, Prisma, Redis, REST API, авторизація JWT (access + refresh), рольове розмежування доступу згідно з таблицею 5 ТЗ.

## 4. Зміна 2.3 — реалізація SEO-вимог

**Розділ ТЗ:** 20.4 «Сумісність, адаптивність та SEO»

| | |
|---|---|
| **Було** | Серверний рендеринг сторінок каталогу та курсів (Next.js) |
| **Стало** | Односторінковий застосунок (Vite) + динамічні мета-теги, мікророзмітка Schema.org через JSON-LD (Course, Product), людинозрозумілі URL зі slug, `sitemap.xml`, `robots.txt` |

**Обґрунтування.** Пряме наслідування зміни 2.1: Next.js як фреймворк орієнтований на TypeScript-стек і вимагав би окремої міграції клієнтської частини.

**Наслідки.** Індексація каталогу пошуковими системами буде повільнішою, ніж за серверного рендерингу. Для дипломного проєкту, який працює в демонстраційному режимі (розділ 23 ТЗ) і не залучає реальний трафік, це не є критичним.

**Серверний рендеринг переноситься до другої черги** (розділ 3.3 ТЗ).
